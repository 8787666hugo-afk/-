關於我

我從高職電子科一路轉到資訊管理，習慣從系統層級思考問題：遇到錯誤時不接受繞過的做法， 而是追到根本原因為止。這個習慣在 SAP 組織架構設定與跨系統整合上特別有用—— 多數卡關並不是操作錯誤，而是前置設定缺了一環。

目前專注在製造業的需求規劃領域，把 SAP 標準功能與外部訊號結合， 讓預測結果既可解釋、又能反映真實市場事件。中程目標是進入 ERP 顧問領域。

代表專案

SAP S/4HANA 導入 ・ AI 輔助需求預測架構

製造業客戶 S/4HANA 導入｜AI 輔助需求預測

角色：需求預測架構設計與整合開發 ・ 模組：PP / MM / SD

客戶的核心困境是結構性的時間落差：關鍵原料採購前置期約 3 個月， 但客戶期望交期僅 1 個月。這使得「預測準確度」直接決定備料策略能否成立。

我設計的是混合式三階段架構，刻意保留 SAP 統計基準線作為備援， 而不是讓 AI 取代整條預測邏輯——這樣才具備可解釋性，AI 服務異常時也能優雅降級。

Stage 1｜基準線以 SAP 標準統計預測產出基礎需求量
Stage 2｜殘差修正Python 模型補捉統計方法抓不到的外部事件訊號
Stage 3｜寫回 SAP透過 BAPI 寫回計畫獨立需求，驅動 MPS／MRP
  • ABAP 自建程式
  • BAPI 整合
  • Python 服務
  • Gemini API
  • 43 個月歷史資料訓練
  • 80/20 時序切分
  • 信賴門檻人工覆核機制

企業組織架構與 SD 銷售流程 從零建置

教學實作環境 ・ 情境設定：馬達製造商採用數量合約

完整建立公司代碼、控制範圍、工廠、採購組織、銷售組織、配銷通路、產品線 及各層指派關係，並串起物料主檔 → 儲存地點 → 庫存 → 銷售訂單的完整鏈路。

過程中自行診斷並解決工廠與公司代碼指派缺漏、MM 期間未開通等典型阻礙， 能明確指出每個錯誤訊息背後真正缺少的前置設定。
